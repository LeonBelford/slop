# Recipes: the usual changes, step by step

Written for small models: do exactly these steps, in this order, and nothing else. Every recipe ends with the checks that must be green.
Read `PROJECT_MAP.md` for the layout and `docs/MODULES.md` for the signatures of every module.

## Add a feature flag
1. `core/cfa_flow.py`: add `"<flag>": True` to `FEATURE_DEFAULTS`.
2. `core/cfutil.py`: add the same key to `DEFAULT_CONFIG["features"]` (both dicts must match).
3. In the code: `if self.cfg["features"].get("<flag>", True):`.
4. Document the flag in `README.md` (feature list) and test both states.

## Add a new Python module
1. Create it under `core/`, `infra/`, `dash/` or `webapi/`; keep it under 700 lines and start it with a one-line docstring.
2. Add one row to `PROJECT_MAP.md` (the path in backticks must exist, `tests/test_project_map.py` checks it).
3. Add `tests/test_<name>.py` with `unittest`, mocks instead of real Ollama or Aider.
4. If `selfimprove.py` must see the package, it is already globbed (`core`, `infra`, `dash`, `webapi`, `bench`).
5. `docs/MODULES.md` is regenerated by `make cards` (self-improve does it after every kept step).

## Add a pipeline step to the build
1. The step is a method of the matching mixin (`core/cfa_build.py`, `cfa_flow.py`, `cfa_plan.py`, `cfa_split.py`).
2. Register the step name in the pipelines of `core/progress.py` (`AGENT_PIPELINE`, `TOOL_PIPELINE`) so the UI shows it; steps that cannot run for a project are hidden.
3. Put it behind a feature flag (recipe above) and log with `self.phase(...)` / `self.log(...)`.
4. Failures must end in a task `reason` (`Backlog.set(..., reason=...)`), never silently.

## Add a dashboard tile (project dashboard)
1. Data: add a key to `extras` in `dash/pdextra.py`; the endpoint `webapi/dashboard.py` returns it.
2. UI: add the tile to the `PD_WIDGETS` registry in `web/projdash.js` (id, title, render function, default size).
3. `node --check web/projdash.js`, then look at it in the browser.

## Add an API route or UI action
1. GET routes: `webui.py` route table (the `/api/project/<n>/<what>` regex) and a method on `webapi/project.py`.
2. POST actions: `Service.act` in `webui.py`; long jobs start via `spawn(key, [...], out)` and `scripts/run.sh`.
3. Errors: raise `UiError(message, code)`.

## Add a self-improve evidence rule
1. `dash/sievidence.py`: add a row to `RULES` (metric name, test, area, text with `{pct}` or `{n}`).
2. Add a test in `tests/test_sievidence.py` with a fake diagnostics dict.

## Add a benchmark task
1. `bench/tasks.json`: id, prompt, seed files, `check` snippet (exit 0 = pass).
2. `python3 bench/run.py --label base --tasks <id>` and keep `bench/results/base.json` as the baseline for the gate (`SI_BENCH_GATE=warn`).

## Fix a bug
1. Write the failing test first; the fix must add at least one new test function (regression policy, `agent/regressions.jsonl`).
2. Never delete or loosen an existing test.

## Always, before you finish
`make lint`, `python3 -m unittest discover -s tests`, `python3 codefactory.py selftest`, update `README.md` and `PROJECT_MAP.md`.
